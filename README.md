# Портфолио — Aisultan Aitmagambetuly

Одностраничный сайт-портфолио: Vue 3 + TypeScript + Vite на фронте, PHP-эндпоинт
для отправки заявок в WhatsApp через Green API.

## Язык дизайна: печатное досье

Сайт намеренно сделан не в вебовой манере. Тёмный фон, циановый акцент,
стеклянные карточки со свечением, чипы и псевдотерминал в углу — набор,
который сегодня выглядит как подпись генератора. Здесь вместо этого:

- **бумага и вермильон** вместо тёмного стекла, **нулевые радиусы** — печать
  не знает скруглений;
- структуру держат **волосяные линейки и типографика**, а не тени и заливки;
- **мастхед** с датлайном выпуска вместо hero с печатающимся текстом;
- **стек как карта плотности**: кегль слова = уровень владения, читается
  за секунду, без одинаковых «звёздочек» и чипов;
- **опыт как реестр** — печатная таблица вместо таймлайна со светящимися точками;
- **кейсы как развороты** с чертежом системы и дельтой «было → стало»:
  ценность работы измеряется разницей состояний;
- **чертежи вместо скриншотов** — макет браузера показывает, что сайт выглядит
  как сайт; схема показывает, что именно построено;
- **колофон** вместо ряда иконок соцсетей.

Две функциональные особенности:

- **Режим доступности** — три темы контраста (дневная, ночная, высокий контраст),
  масштаб шрифта, интервалы, отключение анимации и изображений, с сохранением
  настроек. Это зеркало рабочего кейса: версия для слабовидящих, которую
  я делал для государственного портала.
- **Форма пишет прямо в WhatsApp** — не почтовая очередь, а сообщение в мессенджер
  за секунды. Токен Green API живёт только на сервере.

Интерфейс на двух языках (RU/EN), тексты типизированы: забытый перевод падает
на `vue-tsc`, а не в проде.

## Быстрый старт

```bash
npm install
cp api/.env.example api/.env   # заполнить, см. ниже
npm run dev                    # http://localhost:5173
```

В dev-режиме форму обслуживает плагин Vite (`server/greenApiDevProxy.ts`) — он
повторяет контракт PHP-эндпоинта, так что WhatsApp работает без локального PHP.
Если `api/.env` не заполнен, форма честно скажет «ещё не подключена».

```bash
npm run build       # сборка в dist/ + проверка типов
npm run preview     # посмотреть собранную версию
npm run typecheck   # только типы
```

> `npm run preview` отдаёт статику без PHP, поэтому форма там вернёт «не подключена».
> Это ожидаемо: проверять отправку нужно в `npm run dev` или на сервере с PHP.

## Подключение WhatsApp (Green API)

1. Зарегистрируйтесь на [green-api.com](https://green-api.com) и создайте инстанс.
2. В консоли отсканируйте QR-код телефоном, с которого будете отвечать.
   Инстанс должен перейти в состояние `authorized`.
3. Скопируйте из карточки инстанса `idInstance`, `apiTokenInstance` и `apiUrl`.
4. Заполните `api/.env`:

```ini
GREEN_API_HOST=https://7103.api.greenapi.com   # apiUrl из консоли
GREEN_API_ID=7103xxxxxx                         # idInstance
GREEN_API_TOKEN=xxxxxxxxxxxxxxxxxxxx            # apiTokenInstance
OWNER_PHONE=77077238960                         # куда приходят заявки, только цифры
```

Важно:

- **`apiUrl` у новых инстансов персональный** (`https://7103.api.greenapi.com`),
  а не общий `https://api.green-api.com`. Возьмите значение из консоли, иначе
  запросы будут отклоняться.
- `OWNER_PHONE` — только цифры с кодом страны, без `+`, пробелов и дефисов.
- Телефон нигде не попадает в HTML. Кнопка «написать напрямую» идёт через
  `GET /api/whatsapp.php?go=wa`, который редиректит на `wa.me` уже на сервере —
  парсерам номер из разметки не достанется.

### Подтверждение гостю (необязательно)

`SEND_CONFIRMATION=1` — если гость оставил номер, ему уходит ответное сообщение
«ваше сообщение получено». Расходует сообщения инстанса, на бесплатном тарифе
лучше держать `0`.

### Проверка эндпоинта

```bash
# должен вернуть 302 на wa.me
curl -i "https://ваш-домен/api/whatsapp.php?go=wa"
```

## Публикация бесплатно

Загвоздка одна: форма работает на PHP, а бесплатные хостинги статики его не
выполняют. Поэтому в проекте лежат **две реализации одного эндпоинта**:

| Файл | Где работает |
|---|---|
| `api/whatsapp.php` | обычный хостинг с PHP 8.1+ |
| `functions/api/whatsapp.js` | Cloudflare Pages Functions |
| `server/greenApiDevProxy.ts` | локальный `npm run dev` |

Контракт у всех трёх одинаковый, фронт разницы не видит.

### Вариант 1 — Cloudflare Pages (рекомендую)

Бесплатно: безлимитный трафик, свой домен, SSL, и **форма работает** —
serverless-функция лежит в `functions/`. Узлы есть в Алматы, для казахстанской
аудитории это быстрее европейских хостингов.

1. Создать репозиторий на GitHub и запушить проект (команды ниже).
2. На [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages** →
   **Create** → **Pages** → **Connect to Git**, выбрать репозиторий.
3. Настройки сборки:
   - Framework preset: **Vue**
   - Build command: `npm run build`
   - Build output directory: `dist`
4. **Settings → Environment variables** → добавить для Production:

   | Переменная | Значение |
   |---|---|
   | `GREEN_API_HOST` | `apiUrl` из консоли Green API |
   | `GREEN_API_ID` | `idInstance` |
   | `GREEN_API_TOKEN` | `apiTokenInstance` — отметить **Encrypt** |
   | `OWNER_PHONE` | `77077238960` |
   | `SEND_CONFIRMATION` | `0` |

5. Передеплоить. Сайт поднимется на `<project>.pages.dev`.

Проверить, что эндпоинт жив:

```bash
curl -i "https://<project>.pages.dev/api/whatsapp.php?go=wa"   # ждём 302 на wa.me
```

**Ограничение частоты** (необязательно). Без хранилища форма опирается только
на honeypot и отсечку по времени. Чтобы включить лимит по IP:
**Workers & Pages → KV** → создать namespace, затем в проекте
**Settings → Functions → KV namespace bindings** добавить биндинг с именем
`RATE_LIMIT_KV`. Функция подхватит его сама.

**Свой домен**: Custom domains → добавить `aitmagambet.kz`, перенести NS-записи
на Cloudflare. Домен платный, хостинг — нет.

### Вариант 2 — Netlify или Vercel

Работают так же, но функцию придётся переписать под их формат
(`netlify/functions/` или `api/` у Vercel). Логика в `functions/api/whatsapp.js`
переносится почти дословно — меняется только сигнатура обработчика.
У Vercel бесплатный тариф Hobby рассчитан на некоммерческое использование;
портфолио под это подходит.

### Вариант 3 — GitHub Pages

Проще всего, но **форма работать не будет**: там только статика, без функций.
Гость увидит honest-сообщение «форма ещё не подключена», почта и Telegram
останутся рабочими. Если этого достаточно — в репозитории Settings → Pages,
источник GitHub Actions, workflow для Vite.

## Деплой

Сборка — статика плюс один PHP-файл. Подойдёт любой хостинг с PHP 8.1+
(нужны расширения **curl** и **mbstring**).

```bash
npm run build
# на сервер: содержимое dist/ → в корень сайта
#            api/whatsapp.php + api/.env → в <корень>/api/
```

Итоговая структура на сервере:

```
/var/www/portfolio/
├── index.html          # из dist/
├── assets/             # из dist/
├── favicon.svg
├── robots.txt
├── sitemap.xml
└── api/
    ├── whatsapp.php
    └── .env            # НЕ в git, права 600
```

### nginx + PHP-FPM

Готовый конфиг с HTTPS-редиректами, CSP и защитой `.env` лежит в
[`deploy/nginx.conf.example`](deploy/nginx.conf.example). Минимум, который нужен:

```nginx
server {
    listen 443 ssl http2;
    server_name aitmagambet.kz;
    root /var/www/portfolio;
    index index.html;

    # SPA: один HTML на все маршруты
    location / {
        try_files $uri $uri/ /index.html;
    }

    location ~ ^/api/.+\.php$ {
        include fastcgi_params;
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    }

    # .env не должен отдаваться по HTTP ни при каких условиях
    location ~ /\.(env|git) {
        deny all;
        return 404;
    }

    # Хеши в именах файлов позволяют кэшировать надолго
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

### Apache

`.env` уже прикрыт правилом `location`/`deny` в nginx; на Apache добавьте в `.htaccess`:

```apache
<FilesMatch "^\.env">
    Require all denied
</FilesMatch>
```

### Статический хостинг без PHP

Если разместить на GitHub Pages или Netlify, PHP работать не будет. Варианты:

- перенести логику из `api/whatsapp.php` в serverless-функцию (контракт тот же:
  `POST` c JSON и `GET ?go=wa`);
- указать `VITE_API_ENDPOINT` на отдельный домен, где PHP есть.

## Как это устроено

```
src/
├── content/            # весь текст сайта, ru.ts и en.ts по одной схеме types.ts
├── composables/
│   ├── useI18n.ts      # язык: определение, переключение, сохранение
│   ├── useA11y.ts      # режим доступности → data-атрибуты и CSS-переменные на <html>
│   └── useReveal.ts    # v-reveal и подсветка активной секции, один IntersectionObserver
├── components/         # полосы страницы и переиспользуемые части
│   └── SystemDiagram.vue   # чертежи систем вместо скриншотов проектов
├── api/whatsapp.ts     # единственное место, знающее про эндпоинт
└── styles/
    ├── _vars.scss      # брейкпоинты и миксины (подключается автоматически)
    └── main.scss       # токены, три темы контраста, типографика, примитивы

api/whatsapp.php        # продакшн-эндпоинт: валидация, антиспам, Green API
server/greenApiDevProxy.ts  # тот же контракт для npm run dev
```

Решения, которые стоит знать при правках:

- **Темы — на CSS-переменных, а не на SCSS-переменных.** Иначе три схемы контраста
  потребовали бы трёх сборок.
- **Размеры в rem, миксин `fluid()` тоже отдаёт rem, но наклон безразмерный.**
  `--font-scale` двигает `html { font-size }`, и заголовки обязаны расти вместе
  с текстом (WCAG 1.4.4). Важно: в `clamp()` нельзя умножать `rem` на `px` —
  произведение двух длин невалидно, и тогда объявление отбрасывается целиком,
  а кегль молча падает на дефолт браузера.
- **Интерлиньяж мастхеда — 1.06, не ниже.** В кириллице бревис «Й» и точки «Ё»
  стоят выше капительной высоты: на плотном интерлиньяже они врезаются
  в строку выше. С латиницей этой проблемы не видно.
- **Шрифты подобраны с полной кириллицей**: Golos Text (заголовки и текст),
  Spectral (лид, выноски, курсив), IBM Plex Mono (данные, подписи, маргиналии).
  Проверяйте субсет перед заменой — часть популярных гарнитур не несёт кириллицу
  и молча уходит в fallback.
- **Контент типизирован одной схемой** (`src/content/types.ts`). Добавили поле в
  `ru.ts` — сборка не пройдёт, пока не добавите его в `en.ts`.
- **Номера полос 01–09 совпадают с пунктами оглавления.** Добавляете раздел —
  добавьте его и в `nav.items`, иначе колонтитул начнёт врать.

## Антиспам в форме

Четыре уровня, без капчи:

1. **Honeypot** — скрытое поле `website`. Заполнено → отвечаем `200 ok`, ничего
   не отправляя: бот не должен понять, что его отсекли.
2. **Минимальное время** — отправка быстрее трёх секунд после открытия страницы
   обрабатывается так же тихо.
3. **Ограничение частоты** — 3 сообщения с одного IP за 10 минут, файловое
   хранилище во временной директории, без БД. Настраивается в `.env`.
4. **Валидация на сервере** — независимо от клиентской: длины полей, формат
   телефона или почты, обрезка управляющих символов.

Ответы наружу не содержат деталей Green API — только категорию ошибки.
Диагностика пишется в `LOG_FILE`, если он задан (держите его вне публичной папки).

## Проверено

Вёрстка прогнана скриптом на Playwright по 78 комбинациям: 13 ширин
(360…1920), три масштаба шрифта (100/130/140%) и два языка. Проверялось
и переполнение страницы, и переполнение **текста внутри блоков** — второе
важнее: элемент может оставаться в своих границах, а глифы уже вылезать.

Клавиатура и семантика: skip-link первым табом, ловушка фокуса в модалке
кейса, Escape закрывает модалку и панель доступности с возвратом фокуса,
один `h1`, без пропусков уровней заголовков, все поля и кнопки с именами.

PHP-эндпоинт проверен на 8.2 и 8.4: honeypot, отсечка по времени, валидация,
ограничение частоты, редирект на `wa.me`, коды ответов 400/405/422/429/502.
